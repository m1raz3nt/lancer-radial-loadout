# Lancer Radial Loadout

Модуль для [Foundry VTT](https://foundryvtt.com/) и системы **[LANCER](https://foundryvtt.com/packages/lancer)**.

При наведении на токен вокруг него появляются радиальные слоты. В них назначаются оружие и системы меха, и активируются одним кликом — без открытия листа персонажа.

## Возможности

- Слоты появляются **при наведении** на токен, а не при выборе. Вокруг токена — «безопасная зона»: пока курсор в ней, кружки не пропадают. Зона не перехватывает клики, соседние токены остаются доступны.
- Активация идёт через штатный **Lancer Flow API**, то есть с обычной автоматикой системы — нагрев, списание Limited, экономика действий.
- **Цвет каждого слота** выбирается отдельно: стандартный, красный, зелёный, синий, розовый, серый.
- Бейдж «текущее/максимум» для предметов с тегом Limited; сломанные и исчерпанные подсвечиваются отдельно.
- Радиус раскладки подстраивается под размер токена, поэтому на крупных мехах кружки не ложатся поверх модельки.

## Управление

| Действие | Что делает |
|---|---|
| **ЛКМ** по слоту | Активация. Оружие → бросок атаки, система → активация действия, иначе карточка предмета |
| **ПКМ** по слоту | Назначить/сменить предмет и выбрать цвет слота |
| **ЛКМ** по пустому слоту | То же окно назначения |
| **Shift+ЛКМ** | Счётчик Limited −1 (без броска) |
| **Shift+ПКМ** | Счётчик Limited +1 (без броска) |

Какие предметы можно класть в слот: `mech_weapon`, `mech_system`, `npc_feature`, `pilot_weapon`, `pilot_gear`.

## Кто видит слоты

Игрок видит радиаль на токенах, которыми владеет. Для меха засчитывается и **Owner на связанном пилоте** — в LANCER это разные актёры с раздельными правами.

GM по умолчанию видит слоты только там, где актёром управляет какой-нибудь игрок; настройка `gmSeesAll` снимает ограничение.

> **Показ и запись — разные права.** Радиаль отрисуется и по правам на пилоте, но назначение предмета в слот и ручная правка счётчика меняют самого актёра меха. Без **Owner на меху** они не сработают — модуль покажет предупреждение вместо ошибки. Проще всего выдать игроку Owner и на меха: ПКМ по актёру в сайдбаре → *Ownership*.

## Установка

В Foundry: **Add-on Modules → Install Module** → вставить manifest URL:

```
https://raw.githubusercontent.com/m1raz3nt/lancer-radial-loadout/refs/heads/main/module.json
```

Манифест указывает на `main`, а не на `releases/latest`: часть релизов помечена pre-release, а GitHub исключает такие из `latest`.

## Настройки модуля

*Configure Settings → Module Settings → Lancer Radial Loadout*:

| Настройка | Область | По умолчанию | Что делает |
|---|---|---|---|
| GM видит кружки на всех актёрах (`gmSeesAll`) | world | выкл | Выкл: GM видит слоты только там, где актёром управляет игрок. Вкл: на всех мехах/NPC/пилотах |
| Показывать счётчик расходов (`showUses`) | world | вкл | Бейдж «текущее/максимум» для предметов с тегом Limited |
| Подсвечивать безопасную зону (`showSafeZone`) | client | выкл | Едва заметное кольцо вокруг токена, в котором кружки не пропадают |

Геометрия задаётся константами в начале `scripts/main.js`: `SLOT_COUNT` (число кружков), `RADIUS` (минимальный радиус), `SAFE_PAD` (насколько зона шире кружков), `HIDE_DELAY`. Палитра — объект `SLOT_COLORS` там же: добавить цвет значит дописать в него строку.

## Выпуск релиза

1. Поднять `version` в `module.json` и запушить в `main`.
2. **Releases → Draft a new release** → *Choose a tag* → создать тег `vX.Y.Z` → **Publish**.

Workflow `.github/workflows/release.yml` подставит версию из тега и URL в `module.json`, соберёт `module.zip` с манифестом **в корне архива** и приложит оба файла к релизу.

Два правила, иначе обновления у пользователей ломаются:

- **Имя тега обязано совпадать с `version` в `module.json`.** CI берёт версию из тега, а Foundry сверяется с манифестом на `main` — при расхождении он будет бесконечно предлагать обновление. Сборка на этом падает специально.
- **Релиз нужно создавать, а не переименовывать тег у существующего.** Событие `published` при редактировании опубликованного релиза не наступает, CI не запустится, и к релизу останутся ассеты от прошлой версии. Если так уже вышло — удалить релиз (тег останется) и создать заново, выбрав этот тег в списке.

## Совместимость

Foundry **v12–v13**, система `lancer`. Диалог назначения работает через `DialogV2`, со старым `Dialog` в качестве запасного пути для ранних сборок v12.
